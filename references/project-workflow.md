# Project workflow

Use an empty or new directory for each talk, such as `projects/example`. Run the commands from the skill directory or use full script paths. Python 3.11 or later, `latexmk`, `xelatex`, and PyMuPDF are required for PDF generation and inspection. The template also requires the Beamer, xeCJK, unicode-math, and TikZ packages.

```text
projects/example/
  .paper-to-slides                 created by init
  sources/                         created by import-sources
    manifest.json                  source paths, URLs, and hashes
    manuscript/                    original PDF or LaTeX tree, PDF reading index
    notes/                         copy of the presenter's Markdown
    supplements/                   copies of optional files and PDF reading indexes
  outline.md                       reviewed plan
  speaker-notes.md                 page-by-page spoken notes for PPTX export
  source-review/                   working page images from the source paper, if needed
  slides/
    main.tex                       authored Beamer entry point
    template.sty                   local theme if used
    figures/                       figures used by the authored deck
  build/                           generated by build_pdf.py
    main.pdf                       candidate that passed automated checks
    main.pptx                      optional image deck with native speaker notes
    check.json                     automated report
    compile.log                    latexmk console output
    latex/                         XeLaTeX log, candidate PDF, and auxiliary files
    pages/                         one rendered PNG per PDF page for visual review
```

1. Run `python scripts/project_manager.py init projects/example`, then `python scripts/project_manager.py import-sources projects/example` with the appropriate [source options](source-preparation.md). The import copies supplied files into `sources/` and preserves their original locations. Use `sources/` as a read-only archive. Copy any source figure needed by the slides into `slides/figures/` so the authored deck can be delivered with its local dependencies.
2. Write `outline.md` with [precise evidence links](evidence-review.md). Run `python scripts/check_evidence.py projects/example` and verify the claims against the linked sources before requesting outline approval. After approval, write `slides/main.tex` and place its dependencies under `slides/`.
3. Run `python scripts/build_pdf.py build projects/example`. The script starts with a fresh `build/`, compiles with XeLaTeX, reads the final `build/latex/main.log`, opens the candidate PDF, and renders one PNG per PDF page. Compilation failures, overfull horizontal or vertical boxes, missing glyphs, unresolved references or citations, and extractable text crossing a PDF page boundary fail the automated checks. `check.json` records the compiler log line or PDF page where available. Other LaTeX warnings, including font substitutions, are available for review. A failed build keeps its available log and previews in `build/`. A passing build writes `build/main.pdf`.
4. Review all PNGs for clipped or overlapping formulas, legibility, and correspondence to the outline. The automated checks cover TeX box overflow and extractable text at page boundaries. Formulas drawn as vector shapes or embedded in images need visual inspection, as does overlap that stays within page bounds. After edits, run `build` again. `python scripts/build_pdf.py check projects/example` reruns the checks on the saved candidate and detects edits under `slides/` since compilation. Rerun `check_evidence.py` on the final outline and match the projected formulas, reported values and conclusions to the cited passages before delivery.

5. For a requested PowerPoint, prepare `speaker-notes.md` at the project root and run `python scripts/export_pptx.py projects/example`. After a PDF rebuild, rerun the export to regenerate `build/main.pptx`. Editing only the notes requires just the export command. See [PPTX export](pptx-export.md) for the note format and standalone PDF command.

Run `python scripts/project_manager.py status projects/example` to locate the expected files. Run `clean` with the same project path to discard `build/` while keeping the outline, archived materials, and authored slides. To remove the entire managed project, run `python scripts/project_manager.py delete projects/example --yes`. This removes the project's archive and deck along with the build outputs. Files supplied from outside the project remain at their original paths.

Project commands that write files run one at a time. If a process is forcibly terminated and leaves `.paper-to-slides.lock` behind, confirm the project has no running command before removing the lock file and retrying.
